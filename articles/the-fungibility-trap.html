The Fungibility Trap

Saturday, 2:00 AM. Your phone buzzes. PagerDuty flags a critical alert: the primary LLM provider is returning HTTP 429s across the entire cluster. Dashboard metrics show flat traffic and normal request volume, yet the global Tokens Per Minute (TPM) quota is entirely exhausted. Tracing the offending traffic reveals a single enterprise customer running an experimental summarization agent. The agent choked on a malformed PDF. Instead of failing gracefully, it entered a recursive evaluation loop, demanding the model "try a different extraction strategy." One request per second. Your Request Per Minute (RPM) circuit breakers never tripped. Each request, however, carried a compounding context window. Sunrise brought a zero balance on the monthly API budget.

Before Belief

Requests are fungible. Rate limiting is a network concern.

After Belief

Requests are non-fungible. Cost governance belongs to the semantic layer.

Counting The Rain

You are counting the wrong beans. Standard infrastructure assumes requests are fungible—one HTTP POST roughly equals another in compute and cost. Probabilistic AI systems shatter this assumption. A simple classification call costs fractions of a cent. An agentic loop carrying a 100k-token context window costs dollars. If your circuit breakers only measure HTTP verbs, you are trying to stop a flood by counting raindrops.

Pattern: Semantic Cost Firewalls

Problem: AI workloads exhibit extreme variance in resource consumption.

Forces: Token billing, recursive loops, RPM blindness, noisy neighbors.

Solution: Token-aware circuit breakers and workflow ceilings.

Consequences: Absolute blast-radius containment.

Cost governance in AI is functionally identical to garbage collection in memory management—both require aggressive, automated reclamation before the system panics and crashes.

Starving The Queue

When Kong released advanced token-based rate limiting, they acknowledged that traditional request limits fail for LLM traffic. The gateway must intercept the stream, count the completion tokens, and enforce a hard stop. Similarly, background queueing platforms discovered that API-level throttling is insufficient; you must enforce per-tenant concurrency limits in the job queue itself.
