Feedback Eats Itself

February 18, 2025 · Data & Feedback Loops
Common Belief
Feedback loops make AI systems better over time.
The Reframe
Feedback loops make AI systems narrower — and narrow looks like better until the edges collapse.

In December 2024, users across Reddit, X, and the OpenAI developer forum reported the same thing independently: ChatGPT had gotten lazy. Responses were shorter. Code was less complete. Step-by-step reasoning stopped mid-way. The model hadn't crashed. It hadn't been downgraded. By every aggregate satisfaction metric OpenAI tracked, it was performing better — users were upvoting responses at higher rates than ever.

The pipeline had five layers: the ChatGPT interface collecting thumbs-up and thumbs-down signals; a feedback aggregation layer converting those into preference pairs; a reward model trained on human-labeled data via Scale AI, scoring new responses; a PPO optimization step updating GPT-4's weights based on that reward signal; and a deployment layer serving the updated model to all users. The gap sat between layers two and three — nothing measured whether the feedback distribution itself had shifted. The reward model was trained once, then applied indefinitely.

The system was doing exactly what its feedback loop asked. That was the problem.

The loop doesn't improve the system. It narrows it. And narrow looks like better on a dashboard right up until the moment someone asks the system to do something it used to handle.

The Lie Your Dashboard Tells

The common mental model says: collect user feedback, retrain, repeat. Each cycle moves the system closer to what users want.

What actually happens is that each cycle moves the system closer to what users upvote — and what users upvote is systematically biased toward concise, familiar, low-effort-to-evaluate outputs. Thorough reasoning, creative alternatives, and edge-case handling don't get upvoted because most users don't recognize them when they see them. The feedback signal doesn't just miss these capabilities — it actively punishes them, because a thorough response takes longer to read and a creative one is harder to evaluate.

The turn: aggregate metric improvement and capability regression are not just different axes — they're often anti-correlated in feedback loops. The dashboard is measuring the wrong thing, and the loop amplifies the error.

People upvote answers that feel right, not answers that are right. There's a difference, and feedback loops can't see it.

Same Wound, Different Symptom

The pattern isn't limited to ChatGPT. Google's AI Overviews use click-through signals as feedback for overview generation. By January 2025, SEO analysts had documented that the system was amplifying sensational claims in overviews — because clicks correlate with curiosity and controversy, not truth. Same structure, different proxy metric, same silent degradation.

A January 2025 Oxford study validated the underlying mechanism with hard numbers. Using LLaMA-2 fine-tuned through Hugging Face's TRL library, researchers showed that even a 5% contamination rate of a model's own synthetic outputs in training data led to measurable distributional narrowing within two to three cycles. Vocabulary diversity — unique tokens per 10k generated — dropped. KL divergence from the original distribution increased monotonically. The contamination didn't have to be bad data. High-quality synthetic data caused the same narrowing, because any synthetic output is necessarily a subset of the original distribution. Each round prunes the tails.

▶ Quarantine Boundary — Pattern Card
Problem
A feedback loop improves aggregate metrics while systematically narrowing capability distribution — invisible to standard monitoring until regression is entrenched.
Forces
Need feedback to improve, but feedback is a biased sample. Need to retrain to deploy, but biased feedback narrows distribution. Need speed, but distributional shift is invisible to standard metrics.
Solution
Isolation boundary between feedback collection and any weight-modifying path. Every batch is compared against a held-out reference set frozen at deployment. Checks: length distribution, vocabulary diversity, topic coverage, performance on hard examples the feedback signal would never generate. Shifted batches are held for human review, not discarded.
Consequences
Gains: detection of silent regression before compounding; named, auditable checkpoint for postmortems. Costs: some retraining velocity lost; operational burden of reference-set maintenance and comparison pipeline.

Why Filtering Fails

The instinct is to fix this with better filtering — throw out low-quality feedback, weight high-quality feedback more heavily.

This doesn't work because the problem isn't data quality. It's data completeness. The feedback signal is missing entire regions of the capability space — regions that are hard to evaluate but essential for robustness. No amount of filtering recovers what was never measured. The quarantine boundary works because it doesn't try to recover missing signal. It detects when the signal you have has shifted the distribution away from your reference, and it stops the shift before it compounds.

The turn: from "clean the data" to "quarantine the data and measure the disease." The fix isn't in the data — it's in the boundary around the data.

The quarantine boundary is structurally identical to change-data-capture isolation in database replication. In databases, we've known this for thirty years. In AI feedback loops, we're reinventing it incident by incident.

What to Do Tomorrow

Freeze a reference set of 500 hard examples — cases your model handles correctly but that your typical user feedback would never generate — and wire a distributional check against it into your training pipeline. You can build this in a day. The quarantine threshold can start loose and tighten as you observe how much your feedback signal is already drifting.

What's the difference between data quality and data completeness in a feedback loop?
Tap to reveal
Quality is about removing bad samples. Completeness is about whether the signal covers the full capability space. Filtering fixes quality; it cannot fix completeness — missing regions stay missing no matter how clean the rest is.
Why does a quarantine boundary work better than filtering?
Tap to reveal
Because it doesn't try to recover missing signal. It detects when the available signal has shifted the distribution away from a known-good reference, and it halts the shift before it compounds. It's a structural fix, not a data-cleaning fix.
What traditional engineering pattern mirrors the quarantine boundary?
Tap to reveal
Change-data-capture isolation in database replication. A stream of mutations looks valid individually but corrupts the target if applied without checking against a known-good state. Same structure, same failure mode, thirty years of prior art.
