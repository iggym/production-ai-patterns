Silent Budget Breakers

When multi-step AI workflows fail, they rarely throw HTTP 500 errors. Instead, they enter execution loops where step complexity scales context length exponentially rather than linearly. Standard rate limiters evaluate traffic volume at the network edge. They cannot read prompt payloads, calculate branch depth, or evaluate historical execution paths.

In the LiteLLM and LangGraph incident from April 2026, an ambiguous support ticket led an agent to repeatedly execute search tools. Each iteration appended search summaries back into conversation context. The gateway approved every call because the system stayed beneath sixty requests per minute, even as individual context payloads exploded from 4,000 tokens to over 120,000 tokens. Standard gateway rate limiters fail in multi-step agent systems because cost accumulates as a quadratic function of execution depth rather than a linear count of API calls.

The Cost Trap

A similar context blowup hit Sourcegraph Cody deployments in March 2026. A code refactoring workflow ingested entire module source files during recursive multi-file updates. Context payloads surged from 12,000 tokens to 1.8 million tokens per task across four execution steps. Without pre-dispatch budget checks, single tasks consumed daily tenant quotas in under two minutes. Latency-cost co-optimization requires evaluating marginal token density per decision step before dispatching downstream inference requests.

Graph-Aware Token Guard

The Predictive Token-Budget Circuit Breaker pattern solves this by moving cost evaluation from the network edge into the execution orchestrator state machine. Before dispatching an inference call to a model provider, the orchestrator inspects current execution path state. Pre-dispatch dry-run estimation with static graph inspection halts runaway dynamic loops before tokens are consumed.

COUNTERARGUMENTThe primary counterargument to predictive token budgeting is that pre-evaluating execution paths adds system complexity and introduces latency before every inference step.

This objection misses the magnitude of the trade-off. Inspecting local Redis state and calculating path bounds takes between 1 and 3 milliseconds. In contrast, an unhedged model call takes anywhere from 800 to 4,000 milliseconds while incurring irreversible token costs. Spending 2 milliseconds to prevent a $4,000 runaway loop is one of the highest-return operations in software engineering.

Defensive Execution Blueprint

To implement this pattern in your production system, apply this four-step engineering sequence:

  • Define Strict Node Ceilings: Assign explicit token caps for input context and output returns across every tool node in your graph.
  • Externalize Workflow State: Store running token balances and step counts in a low-latency key-value store like Redis rather than keeping state inside local worker memory.
  • Execute Pre-Dispatch Bounds Evaluation: Insert a state verification check immediately before every model invocation step.
  • Implement Deterministic Fallbacks: Design non-probabilistic recovery paths, such as switching to vector search or returning static response templates, for when circuit breakers trip.
RETRIEVAL PRACTICE: KEY DECISION POINTS
Why do standard API gateway rate limiters fail to catch agentic loops? +
Standard gateways evaluate request frequency (RPS) at the network edge without inspecting context payload growth or graph depth. Recursive agent loops pass clean HTTP 200s while spending exponentially on context.
Where must the predictive circuit breaker check be executed? +
Inside the orchestrator state machine immediately before model dispatch, calculating projected upper bounds ($C_{est}$) against a centralized state store like Redis.
